## 3. CHECKPOINT ATOMICITY & CRASH-WINDOW AUDIT

### Failure Window Analysis:
Execution order:
1. `agent._persist_agent_output(output)`
2. PostgreSQL `agent_outputs` `conn.commit()`  <-- **OUTPUT COMMITTED**
3. `agent.run()` returns result
4. `checkpoint_manager.mark_batch_completed(...)`
5. PostgreSQL `agent_checkpoints` `conn.commit()` <-- **CHECKPOINT COMMITTED**

### Controlled Crash-Window Test Results (Pre-Fix):
- A controlled test (`test_crash_window_defect.py`) simulated a process termination in the crash window (immediately after step 2 `agent_outputs` commit, before step 5 `agent_checkpoints` commit).
- **Result Pre-Fix**: Upon resume, `is_batch_completed()` returned `False`. The runner re-executed `agent.run()`, which inserted duplicate rows into `agent_outputs` (**Row count grew from 1 to 2**).
- **Defect Confirmed**: Lack of unique constraint on `agent_outputs` allowed duplicate claim insertions if interrupted during the crash window.

---

## 4. MINIMAL IDEMPOTENCY FIX IMPLEMENTATION

To eliminate duplicate output creation during process restarts, a minimal SQL UPSERT mechanism was added to `agents/agent1_evidence_intelligence/agent.py`:

1. **Unique Index**:
   ```sql
   CREATE UNIQUE INDEX IF NOT EXISTS agent_outputs_case_agent_claim_idx 
   ON agent_outputs (case_id, agent_id, claim);
   ```

2. **Idempotent UPSERT**:
   ```sql
   INSERT INTO agent_outputs 
       (case_id, tenant_id, agent_id, model_used, claim, evidence_ids, confidence, verified, execution_status, flags, created_at)
   VALUES (%s, %s, %s, %s, %s, %s, %s, %s, %s, %s, %s)
   ON CONFLICT (case_id, agent_id, claim) DO UPDATE SET
       tenant_id = EXCLUDED.tenant_id,
       model_used = EXCLUDED.model_used,
       evidence_ids = EXCLUDED.evidence_ids,
       confidence = EXCLUDED.confidence,
       verified = EXCLUDED.verified,
       execution_status = EXCLUDED.execution_status,
       flags = EXCLUDED.flags,
       created_at = EXCLUDED.created_at;
   ```

### Controlled Crash-Window Test Results (Post-Fix):
- Re-running `test_crash_window_defect.py` after the fix:
  - Rows after 1st execution: 1
  - Rows after 2nd execution: 1
- **Result**: **100% IDEMPOTENT**. Re-running uncheckpointed batches updates existing claims cleanly without creating duplicate rows.

## 5. REVISED FAILURE CLASSIFICATION MATRIX

| Failure Scenario | Database Output Action | Checkpoint Action | Retryability | Idempotency Protection |
| :--- | :--- | :--- | :--- | :--- |
| **Successful Batch** | Inserted / Updated | Marked `COMPLETED` | Non-retryable (Completed) | Unique index + UPSERT |
| **Crash after DB commit, before Checkpoint** | Inserted | Un-checkpointed | **Safe Retryable** | **Idempotent UPSERT prevents duplicates** |
| **Malformed JSON** | Fail-closed (0 claims) | Not checkpointed | Retryable | Fails closed |
| **HTTP Read Timeout** | Fail-closed (0 claims) | Not checkpointed | Retryable | Safe under 600s timeout |
| **PostgreSQL Write Failure** | Exception raised | Not checkpointed | Retryable | Unmodified |
