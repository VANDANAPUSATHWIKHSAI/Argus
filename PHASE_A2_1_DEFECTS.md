## 1. AFF Container Support Gap Audit (Critical Special Audit)

### Files Audited
- `raw evidence/phase a/disk/ntfs1-gen0.aff` (277,228 Bytes)
- `raw evidence/phase a/disk/ntfs1-gen1.aff` (8,481,452 Bytes)

### Forensic Header & Container Verification
- **Header Magic**: `AFF10\r\n\x00` (Advanced Forensic Format 1.0 container)
- **Container Characteristics**: AFF 1.0 compressed segment container storing raw disk chunks.

### Toolchain Capability Investigation
- **Sleuth Kit Toolchain**: Bundled Windows TSK binaries (`fls.exe` in `tsk/sleuthkit-4.12.1-win32/bin/fls.exe`) were compiled without static `libaff` library support (`#ifdef HAVE_LIBAFF` not defined during build).
- **Execution Test**: Invoking `fls.exe ntfs1-gen0.aff` fails with error `Image type aff not supported (compiled without libaff)`.
- **Python Package Check**: `pyAFF` / `pyaff4` / `libaff4` are not installed in current Python environment.

### Router & Pipeline Handling
- **Router Recognition**: `ParserRouter` detects magic header `AFF10\r\n\x00` and `.aff` file extension.
- **Status Classification**: Explicitly classified as **`BLOCKED`**.
- **Reason String**: `BLOCKED_MISSING_LIBAFF: Sleuth Kit binaries (fls.exe) compiled without libaff support`.
- **Evidence Integrity**: Both `.aff` files remain 100% untouched in original evidence storage with verified SHA-256 hashes (`bf0291a0ee84...` and `33528f2d44fe...`).
- **No Fabrication**: ARGUS does NOT fabricate parsed records for AFF or claim completed parsing.

### Requirements to Enable AFF Parsing
1. Build or download Windows TSK binaries compiled with `libaff3-dev` / `libaff.lib`.
2. Or integrate `pyaff4` / `pyaff` Python binding module into virtual environment.
3. Integration Point: `FilesystemParser._run_fls()` calls AFF-enabled `fls.exe`.

## 2. DFXML XML Catalog Resolution

### File Audited
- `raw evidence/phase a/disk/ntfs1-gen2.xml` (2,341,489 Bytes)

### Format & Relationship Verification
- **Root Tag**: `<dfxml xmloutputversion="1.0">` generated by `fiwalk v0.5.5`.
- **Evidence Relationship**: Functions as pre-cataloged volume metadata catalog for disk image `ntfs1-gen2.E01`.
- **Resolution**:
  - Routed to `FilesystemParser` via signature check (`<dfxml` tag).
  - Parsed using regex-augmented XML extractor in `FilesystemParser._parse_dfxml_file()`.
  - Extracted **19 file catalog records** (`filename`, `filesize`, `mtime`, `sha256/md5`).
  - Marked as auxiliary forensic metadata without creating duplicate disk image artifacts.
